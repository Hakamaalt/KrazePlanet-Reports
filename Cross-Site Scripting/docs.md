## Title
Reflected XSS - docs.pwnedbox.site

## Description
The `docs.pwnedbox.site` endpoint was tested using the `x8scan` tool to identify potentially reflected GET parameters. A crafted JavaScript payload was then supplied through the `q` parameter to test for possible reflected Cross-Site Scripting (XSS).

## Steps to Reproduce

1. Open a terminal and execute the following command to scan for parameters:

   ```bash
   echo "https://docs.pwnedbox.site/" | x8scan -w params.txt
   ```

2. Observe the transformed GET URL generated by `x8scan`, containing the parameters `fname`, `lname`, and `q`.

3. Open the following crafted URL in a browser:

   ```text
   https://docs.pwnedbox.site/?q=hakama%27%22%3C%3E%3CScriPt%3Ealert(1)%3C/ScriPt%3E
   ```

4. Allow the page to load and observe whether the supplied JavaScript payload executes and displays an alert dialog.

## Impact

If the `q` parameter is confirmed to be vulnerable to reflected XSS, an attacker may craft a malicious URL and trick a victim into opening it. Successful exploitation could allow JavaScript execution in the victim's browser, potentially enabling phishing, page-content manipulation, or unauthorized actions within the context of the affected website.

## Remediation

- Apply context-aware output encoding to all user-controlled input before rendering it in HTML.
- Validate and sanitize input received through the `q` parameter.
- Avoid inserting untrusted input into the page using unsafe JavaScript methods such as `innerHTML`.
- Implement a restrictive Content Security Policy (CSP) to reduce the impact of potential XSS vulnerabilities.
